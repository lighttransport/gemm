# Qwen3.8-27B Q8: 25 tok/s optimization

Goal: at least 25 tok/s on one A64FX node, with end-to-end reference token
identity. The user permits approximate arithmetic. This continues the
[20 tok/s result](qwen38_q8_20tps_51857846.md).

## Configuration and approximation

Same job 51857846, node c25-7001c, normal 2.0 GHz, 48 workers on CPUs 12–59,
2 MiB anonymous pages on N4–N7, staged /local model and login3 HTTP bridge.
No speculative decoding or multi-request batching. Guard at 2 GiB MemAvailable.

The explicit `--q8-mode cmg4-a15` option preserves the Q8_0 weight bytes and
original per-32-element scales. It rearranges each four input bytes per output
row for SVE SDOT. For each 32-element activation block:

- scale = max(abs(x)) / 16256;
- round x / scale to an integer in [-16256, 16256];
- represent the integer as 128 * hi + lo, both signed bytes;
- compute two integer dots and combine them before FP32 conversion/scaling.

This changes activation precision and floating-point reduction order. Original
`--q8-mode cmg4` retains the exact packed path. Token identity is validated on
recorded traces; this does not prove identity for arbitrary inputs.

## Experiments

- a15-v1: quantize inside every record call. Full reference trace 128/128 IDs
  match, max selected-logit error 0.00255966187, RMS 0.000802384166. Warmed
  throughput regressed to 13.639 tok/s because of repeated scalar quantization.
- a15-v2: quantize once per worker/matrix and reuse across output groups.
  Aggregate 14.889 tok/s; 128/128 IDs in all four trials match reference.
- a15-v3: also vectorize activation max reduction, rounding, and byte stores.
  Aggregate 18.549 tok/s; all four trials match, max logit error 0.00255966187.
  A second 128-token matrix-multiplication prompt matches with max error
  0.000932693481 and RMS 0.000309487015.
- a15-v4: shared cooperative quantization with double buffering; prefetch both
  cache lines 8192/8448 bytes ahead. Three trials 21.422, 21.552, 21.847 tok/s;
  aggregate 21.605. All four token traces match reference, same logit error.
  Scratch 11.873 MiB.
- a15-v5: CMG-local arrival counters for shared quantization; explicit
  --fast-swiglu enables cubic-corrected FEXPA and two reciprocal refinements
  in FFN and SSM output gates. TF_HIER_BARRIER=1 and TF_Q8_ROWS=2.
  Three warmed runs 22.719 / 22.655 / 22.716 tok/s, aggregate 22.697.
  All four 128-token traces match, max logit error 0.00204467773, RMS
  0.000622455675.
- a15-v6: optional `cmg4-a15-split` partitions contiguous input tiles within
  each CMG, balancing uneven output-group counts. Boundary partial sums are
  double-buffered and merged in input order by the original output owner.
  Additional scratch is bounded at 96 KiB per packed tensor. This changes
  FP32 reduction grouping and must pass the full token gate. Native split tests
  pass for 6/40/136 output groups, 4/8/4 input tiles, 48 workers, eight epochs.
  It regressed to 21.772 tok/s aggregate (21.791/21.777/21.747), despite all
  four traces matching with max logit error 0.00223731995. Rejected and removed
  from canonical sources; the immutable v6 snapshot preserves the experiment.

The benchmark records IDs and selected logits in memory and prints them after
its timed region. The checker compares each complete warmup/measured trial
against the corrected reference. Missing records, nonfinite logits, differing
IDs/positions, and absent completion summaries fail validation.

Native tests cover integer-dot scalar oracles, activation rounding-error
bounds, and the unchanged exact packed kernel/48-worker partitioning.

Raw results are under `tmp/qwen38-run/results-51857846/` on Fugaku and
`/local/u14346/q27b-51857846/` during the allocation. Immutable source/build
snapshots avoid stale shared-filesystem cache after frontend edits.

## Isolated kernel and synchronization tests

The dot-only one-CMG benchmark (12 workers, 240 MiB, eight passes, median of
three trials) measured 200.626 GB/s with one 4 KiB prefetch. Covering both
256-byte lines gave 218.725 GB/s at 4 KiB and **228.162 GB/s at 8 KiB**.
12/16/24 KiB gave 223.647/227.142/224.597 GB/s. Staging the final scale/FMA
instructions gave 228.355 GB/s at 8 KiB, no material gain, so it was not adopted.

The shared quantizer passes 48-worker, 64-generation stress with deliberately
uneven consumers and fewer input tiles than workers. Zero/tie/endpoint tests,
64 random integer-dot oracles, and quantization error-bound checks pass.

The SwiGLU approximation passes a [-100,100] gate sweep, widths 1..257,
with max absolute error 7.62939453e-06 and max relative error 1.01291316e-06
(where |reference| > 1e-6). This local bound does not establish model identity;
the end-to-end comparison is still required for each selected configuration.

## Continuing after split-column rejection

- a15-v7 uses four separately bound activation workspaces, with local 12-worker
  synchronization. Warm runs: 22.935 / 22.954 / 22.941 tok/s, aggregate 22.944.
  All four traces preserve 128/128 IDs and the v5 selected logits exactly.
- Full-node shape kernels reached 831–878 GB/s. A temporary high-byte-only A8
  kernel did not materially improve bandwidth and was not integrated.
- Cache-line group skews 0..16384 bytes showed no useful gain on the four
  projection shapes. No padding was added.
- Isolated scale tests (after removing concurrent compiler interference) showed
  identical ~284.5 ns/record for FP16 encodings 1, 512, 1023, 1024, 4096, 15360.
  Hugepage full-node runs also matched. No scale rebiasing was implemented.
- a15-v9 tests SSM base-page state placement by head, lossless FP32 storage of
  the 48-row Q8 alpha/beta matrices, and activation reuse between adjacent
  projections sharing the same input. v8 was a failed build, not performance
  evidence. v9 fixes helper placement and scratch/context ownership.
  It regressed to 17.673 tok/s: generic FP32 fallback allocated/copied a row
  on every call, increasing SSM input projection time to 22.273 ms/token.
  All four traces still matched (max logit error 0.00290870667). SSM state
  time improved from about 2.12 to 1.34 ms/token.
- a15-v10 removes that FP32 row allocation/copy with direct SVE dots. Its new
  native integration test verifies exact small-matrix weight expansion,
  48x5120 dot products against a scalar oracle, exact SSM state copying,
  all 48 heads on the expected NUMA nodes, and mapped-state cleanup.
- a15-v11 additionally applies the explicit fast activation option to the
  convolution SiLU step. In-place SiLU gets a separate numerical sweep.
  It also fixes the no-pool small-matrix initialization fallback so a model
  configured for 48 threads still initializes every row when its pool is absent.

The 25 tok/s stretch goal is deferred. The accepted target is at least 24
tok/s, pending final source promotion and housekeeping.

## Accepted 24 tok/s result

The accepted v13 candidate uses `--q8-mode cmg4-a15 --fast-swiglu`,
`TF_HIER_BARRIER=1`, and `TF_Q8_ROWS=2`. Normal 2.0 GHz warmed trials were
24.306 / 24.288 / 24.272 tok/s (24.289 aggregate). Boost-eco 2.2 GHz measured
24.402 tok/s aggregate. Both passed four-trial 128-token identity checks:
128/128 IDs, selected-logit max error 0.0018825531, RMS 0.000602414954.
The independent matrix prompt passed 128/128 IDs with max error 0.00151634216
and RMS 0.00040693484. Minimum normal-run MemAvailable was 3.79 GiB.

A15 activation quantization and fast SiLU/SwiGLU remain opt-in. Exact `cmg4`
remains available as the reference-compatible path. Flat barriers measured
24.281 tok/s and were not selected.


## Normal-clock continuation and memory diagnosis

- v10 direct FP32 dots: 24.037 / 24.280 / 24.347 tok/s, aggregate 24.220,
  stddev 0.133. Four full traces match; max selected-logit error 0.00290870667,
  RMS 0.000705727391.
- v11 adds convolution SiLU: 24.359 / 24.310 / 24.316 tok/s, aggregate 24.328,
  stddev 0.022. Four full traces match; max selected-logit error 0.0018825531,
  RMS 0.000602414954. Minimum sampled MemAvailable 3.531189 GiB.
- A flat-barrier v11 attempt was OOM-killed during loading, before any token
  trace. It is not a performance result. Kernel logs show CMG 0 exhausted
  contiguous 2 MiB pages (zero free blocks >=2 MiB) while other CMGs retained
  headroom. A global MemAvailable guard alone does not catch that condition.
- v12 changes only the launcher allocation policy to `numactl --interleave=4-7`
  for auxiliary allocations. Explicit packed-arena and SSM-state `mbind`
  policies still determine their owner placement. The runner binary is identical
  to v11: SHA256 `4feb2747dccae45ed322a90b0f5377f013b0551221867744a55b7f20d8937ae1`.

A second one-node allocation, job 51862725 on a25-0015c, uses documented
boost-eco mode (`freq=2200,eco_state=2`). It has an independent login3 bridge:
local42428 -> reverse32428 -> compute21264. Results must distinguish this clock
setting from normal 2.0 GHz. The model is staged with direct I/O; inference still
uses exactly one node and one request. The v12 benchmark and a second 128-token
matrix-tutorial prompt are queued behind staging, with reference checks.


## Final allocation-order correction

Normal-clock v12 passed at 24.306 / 24.288 / 24.272 tok/s (aggregate about
24.289), with all four traces unchanged and minimum MemAvailable 3.78931 GiB.
Its flat-barrier comparison also passed, aggregate 24.281; no useful improvement,
so hierarchical synchronization remains selected. The normal-clock matrix
prompt matched 128/128 IDs, max selected-logit error 0.00151634216 and RMS
0.00040693484 (cold whole trace 23.516 tok/s, not the warmed headline).

However, the first boost v12 load was OOM-killed at the same point: output
projection packing after the base-page SSM state remap. Auxiliary interleaving
alone is therefore not a sufficient fix. v13 prefaults the complete, already
capacity-checked per-CMG packed arenas before smaller allocations and delays
base-page SSM remapping until all packed weights, including output, are populated.
This changes allocation order, not arithmetic. It is being tested with a rebuilt
runner and two full model loads on the boost node. The failed v11flat/v12boost
loads produce no throughput or token-identity claims.
