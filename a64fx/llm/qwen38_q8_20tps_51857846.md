# Qwen3.8-27B Q8: 20+ tok/s on one A64FX node

Continuation of [the correctness baseline](qwen38_q8_single_51857846.md).
Goal: sustained single-request decode above 20 tok/s with reference token IDs
preserved, measured over repeated warmed full-model runs.

## Configuration

- Job `51857846`, node `c25-7001c`, **one node at normal 2.0 GHz**.
- 48 workers, CPUs 12–59, four CMG-local anonymous HBM arenas on N4–N7,
  strict 2 MiB pages. No tensor-parallel or multi-request batching.
- Model `/local/u14346/qwen38/Qwen3.8-27B-Q8_0.gguf`.
- Resident decode weights 27.223 GB; packed payload 27.198 GB.
- FP16 KV, prompt `Hello`, speculative decoding disabled.
- Bridge: workstation 42427 -> login3 32427 -> compute 21264.
- Native Fujitsu build, `CC=fcc OPENMP=1`, target's existing `-Kfast` flag.
- Detached sequential runs with a 2 GiB `MemAvailable` guard.

## Changes

1. Retain the preceding FFN producer/consumer ownership correction.
2. Widen packed Q8 records from 64 to **128 output rows**, retaining 128 input
   columns and each original 32-element Q8 scale. Eight independent ascending-K
   FP32 accumulation chains hide conversion/FMA latency. Packing and work
   partitioning use `Q8_K128_N`, so the arena footprint remains unchanged.
3. Issue one **L2 prefetch 4096 bytes ahead per 256 weight bytes**. L1 prefetch
   regressed in the isolated sweep; larger L2 distances were also slower.
4. Report per-trial decode stage timings under `TF_DPROF`, resetting counters
   after prefill so warm decode costs are not confused with startup faults.
5. Use native half widening, vectorize independent PV dimensions, and interleave
   four independent QK scores while preserving each reduction’s FMA order.
6. Extend native exact tests to randomized repeated record accumulation with
   nonzero initial output values (64 trials, four records each).

The packed arithmetic order is unchanged per output row. No activation
quantization, reduced-precision accumulation, or weight replication was added.

## Measurements

| Candidate | One-CMG kernel GB/s | Warm full-model decode tok/s |
| --- | ---: | ---: |
| Corrected 64-row baseline | 111.3 | 13.930 median |
| 128-row, no software prefetch | 155–157 | 17.890 aggregate |
| 128-row, 4 KiB L2 prefetch, 32 steps | 183.8 | 20.414 aggregate |
| Same kernel, 128 steps | — | 19.365 median |
| Native half widening + vector PV, 128 steps | — | 19.935 aggregate |
| Plus four-score QK interleaving, 128 steps | — | **20.300 aggregate** |

The no-prefetch and first prefetched measurements each cover one warmup and
three measured 32-step trials. For the prefetched kernel, individual trials were **20.352,
20.472, 20.418 tok/s**, median **20.418**, population standard deviation
**0.049 tok/s**, and effective bandwidth **555.738 GB/s**. These are model
measurements, not extrapolations from the kernel or streaming benchmark.

The warm prefetched stage profile is approximately (ms/token): attention QKV
2.78, attention output 0.91, SSM input 7.60, preparation 1.07, core 2.04,
output 3.35, FFN gate/up 17.16, down 9.15, vocabulary head 1.81.
Cold SSM preparation remains much slower and variable. The throughput claim
excludes loading and warmup. Aggregate persistent `dprof matvec` counters still
report zero; the stage counters provide the useful measurements here.

Extending the prefetched kernel alone to 128 steps gave 18.533, 19.365,
19.372 tok/s, so the short-run result did not establish sustained 20+ tok/s
at that length. Native half widening and vector PV improved the 128-step
trials to 19.919, 20.028, 19.860 tok/s.

The final candidate, including four-score QK interleaving, achieved **20.438,
20.016, 20.450 tok/s** across three warmed 128-step trials: median **20.438**,
aggregate **20.300**, population standard deviation **0.202 tok/s**, effective
bandwidth **552.623 GB/s**. Attention core cost fell from approximately 2.34 to
1.19 ms/token. Minimum sampled MemAvailable across final trace and benchmark
was **3.911 GiB**, with no guard firing. This reaches the 20+ goal for this
short-context benchmark; longer contexts and other prompts are not established.

The final packed layout streamed at **866.9 GB/s** versus a four-region control
of **876.0 GB/s**, with zero ownership errors and 2 MiB pages on N4–N7.
This layout test preceded attention-only changes, which do not alter arenas.

## Correctness and rejected experiments

- Native scalar-oracle kernel tests and the 48-worker/CMG partition test pass.
- Randomized nonzero read/modify/write accumulation matches the scalar oracle
  exactly across all four records in each of 64 trials.
- Corrected reference versus prefetched candidate: **32/32 token IDs match**;
  selected-logit maximum absolute error **7.43865967e-05**, RMS
  **2.53184367e-05**, below the explicit 0.001 tolerance.
- Exhaustive native FP16 widening tests pass: 63,490 finite/infinite encodings
  are bit-exact; 2,046 NaN encodings remain NaN. Native PV and four-score QK
  tests match scalar ordered FMA, including partial vectors and KV strides.
- Selected logits validate this trace, not all vocabulary logits or all prompts.
- A paired kernel retaining two separate 64-row streams was slower (94–101
  GB/s). A three-stage 64-row pipeline reached only 115.5 GB/s. A 96-row
  register-resident experiment reached 123.4 GB/s. None was promoted.

## Reproduce

Run sequentially inside the existing allocation, with the memory guard described
above. The staged model remains under `/local` and weights are materialized into HBM.

```sh
N=$PWD/tmp/qwen38-run/n128-v5
M=/local/u14346/qwen38/Qwen3.8-27B-Q8_0.gguf
TF_DUMP_TOKENS=1 TF_MODULE_PROFILE=1 "$N/a64fx/llm/run_qwen38_q8_cmg4.sh" "$M" \
  --prompt Hello --max-seq 128 --max-gen 32 --spec-k 0
TF_DPROF=1 "$N/a64fx/llm/run_qwen38_q8_cmg4.sh" "$M" \
  --prompt Hello --max-seq 512 --bench --bench-prompt 1 --bench-gen 128 \
  --bench-warmup 1 --bench-runs 3 --bench-csv
python3 a64fx/llm/test_qwen38_token_trace.py \
  /local/u14346/q27b-51857846/reference-safe.log \
  /local/u14346/q27b-51857846/n128v5-trace.log --max-logit-error 0.001
```
