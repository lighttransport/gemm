## FFN correctness fix

Packed CMG4 projections produce complete 64-row groups, but their barrier-free
SwiGLU consumer used ordinary row partitions. At 17,408 FFN rows and 48 workers,
that can read a neighboring worker's unfinished gate/up outputs. The consumer
now uses exactly the producer's group boundaries, without adding a CMG4 barrier.

Reference/fused Q8 and block64 kernels also produce groups, whose sizes depend
on runtime options. These paths now synchronize before the generic consumer.
The existing BF16 PV matched-group path is unchanged.

The initial CMG4 trace matched all 32 token IDs from an earlier reference, but
selected logits differed by up to 0.27119. Fixing CMG4 alone reduced the maximum
difference against the initial resident reference to 0.00502. These earlier
reference traces also had the consumer race and are not numerical goldens.

## Reproduction

From the worktree inside the allocation:

```sh
M=/local/u14346/qwen38/Qwen3.8-27B-Q8_0.gguf
TMPDIR=$PWD/tmp/fcc make -C a64fx/dequant-pipe test_q8_k128 CC=fcc
./a64fx/dequant-pipe/test_q8_k128
TF_NULL_GEMM=2 NUMA_REPORT=1 a64fx/llm/run_qwen38_q8_cmg4.sh "$M" \
  --max-seq 16 --max-gen 0 --spec-k 0
TF_DUMP_TOKENS=1 TF_MODULE_PROFILE=1 a64fx/llm/run_qwen38_q8_cmg4.sh "$M" \
  --q8-mode reference --prompt Hello --max-seq 128 --max-gen 32 --spec-k 0
TF_DUMP_TOKENS=1 TF_MODULE_PROFILE=1 a64fx/llm/run_qwen38_q8_cmg4.sh "$M" \
  --prompt Hello --max-seq 128 --max-gen 32 --spec-k 0
a64fx/llm/run_qwen38_q8_cmg4.sh "$M" --prompt Hello --max-seq 128 \
  --bench --bench-prompt 1 --bench-gen 32,32,32 \
  --bench-warmup 1 --bench-runs 1 --bench-csv
```

The later `--q8-mode reference` overrides the launcher's CMG4 argument, retaining
resident original Q8 weights. An attempted mmap reference was stopped before
its first token after more than 160 GB of read I/O; it is not a speed result.
Use the resident reference for subsequent checks.

Remote guard/launch scripts and logs are under `tmp/qwen38-run/`, with collected
logs in `tmp/qwen38-run/results-51857846/`. Allocation-local originals are in
`/local/u14346/q27b-51857846/`.

## Final validation

The corrected resident reference and corrected CMG4 both generated the same
32 token IDs for `Hello`. Maximum absolute selected-logit error was
**7.43865967e-05**, RMS **2.53184367e-05**. Two independently loaded corrected
CMG4 runs produced exactly equal token IDs and selected logits. This validates
this prompt and these selected logits, not every vocabulary logit or all prompts.

Against the corrected reference, the original CMG4 run fails a 0.001 tolerance
(maximum error 0.0119591). The much larger 0.27119 historical comparison above
also included an unsafe reference and must not be attributed solely to CMG4.

```sh

python3 a64fx/llm/test_qwen38_token_trace.py \
  "$D/reference-safe.log" "$D/cmg4-repeat.log" --max-logit-error 0.001
```

The standalone native kernel/48-worker partition test also passed. Minimum
sampled `MemAvailable` across resident runs was **3.972 GiB**; the benchmark's
minimum was 3.999 GiB. The guard never fired. The second cold CMG4 run measured
7.522 tok/s, with SSM preparation 58.1 ms/token, despite bit-identical selected
logits. Cold auxiliary-weight/page-fault behavior remains variable; use the
warmed repetitions for the reported steady-state throughput.
